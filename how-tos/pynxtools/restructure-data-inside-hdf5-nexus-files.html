Restructure data inside HDF5/NeXus files¶

Info

This how-to shows a practical workflow for restructuring existing HDF5/NeXus data without rewriting the underlying file manually. The starting point is the list of available keys generated by pynx list-keys, followed by a second conversion pass using the json_map reader.

Often, a file contains the right data, but in a different hierarchy or with different names than the target NeXus application definition expects. Instead of constructing a config file by hand to rewrite the data into a valid NeXus tree, pynxtools allows extracting the HDF5 tree structure from an existing .hdf5/.nxs file and create a mapping that allows you to reconstruct the original file using the pynx convert command. By modifying this template config file, the data can be placed into the desired concepts.

1) Inspect the available keys¶

Start from the file you want to reorganize:

pynx list-keys my_file.nxs

This prints a JSON mapping from logical NeXus-style paths to the corresponding HDF5 source paths. The output looks similar to this:

{
  "/ENTRY[entry]/data": "@data:entry/data",
  "/ENTRY[entry]/data/@units": "@data:entry/data@units",
  "/ENTRY[entry]/SAMPLE[sample]/temperature": "@data:entry/sample/temperature",
  "/ENTRY[entry]/SAMPLE[sample]/temperature/@units": "@data:entry/sample/temperature@units"
}

The keys in this mapping correspond to the Nexus concepts and paths as defined in the config files for the MultiFormatReader. The values are the source paths inside the HDF5 file, using the @data: prefix that the JSON mapping reader provides.

If you need to keep the output for editing, save it to a file:

pynx list-keys my_file.nxs --output keys.json

You can then open keys.json and adjust the mapping to match the structure you want in the new NeXus file.

2) Edit the mapping¶

The mapping is meant to be edited by hand. There are two main ways to change it:

  • Change the key to assign the source value to a different concept.
  • Change the value to assign a different source dataset or attribute to an existing concept. You can also replace these keys with new, constant values.

For example:

{
  "/ENTRY[entry]/SAMPLE[sample]/temperature": "@data:entry/measurement/temperature",
  "/ENTRY[entry]/SAMPLE[sample]/temperature/@units": "@data:entry/measurement/temperature/@units",
  "/ENTRY[entry]/INSTRUMENT[instrument]/detector/count_time": "@data:entry/measurement/count_time",
  "/ENTRY[entry]/INSTRUMENT[instrument]/detector/count_time/@units": "ms"
}

This tells the dataconverter to put the selected data under different NeXus concepts. If the key is changed, the data is moved to a different location in the target file. If the value is changed, the same concept gets populated from a different source field or constant.

Note

This is a useful way to reshape a file without modifying the original dataset. The original HDF5 file stays untouched, and the output file created by the conversion step is changed.

3) Convert the file using the json_map reader¶

Once the mapping is ready, trigger a conversion that writes a new file using the json_map reader:

pynx convert my_file.nxs \
  -c keys.json \
  --reader json_map \
  --nxdl NXyour_application \
  --output restructured_file.nxs

This reads the source file, follows the mapping in keys.json, and writes a new NeXus file that matches the target application definition. The json_map reader is particularly useful here because it applies the mapping literally: it reads the source HDF5 path from the value and writes the result into the target concept defined by the key.

4) Typical workflow summary¶

In practice, the workflow is:

  1. Run pynx list-keys on the original HDF5/NeXus file.
  2. Save the result and edit the keys and values to match the desired target structure.
  3. Run pynx convert with --reader json_map and -c pointing to the edited mapping file.
  4. Inspect the output file and repeat until the resulting hierarchy matches the desired NeXus layout.

This is a simple and robust way to restructure a file without manually reconstructing the source-to-target mapping from scratch.
